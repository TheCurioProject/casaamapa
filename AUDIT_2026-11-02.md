# Revisión técnica de Casa Amapa — 2 de noviembre de 2026

Estado: correcciones locales. No se modificaron reservas, credenciales, pagos ni
el esquema de producción. No se publicó un deployment.

## Incidente de reservas manuales

Se reprodujo con el mismo PostgreSQL y el adaptador Prisma del proyecto, mediante
una transacción sin escrituras:

```text
SELECT pg_advisory_xact_lock(184247931)
P2010: Failed to deserialize column of type 'void'
```

PostgreSQL adquiría el bloqueo correctamente, pero Prisma no podía interpretar
su resultado. La transacción se abortaba antes de crear la reserva y la interfaz
solo mostraba «No se pudo crear la reserva manual». El mismo helper afectaba a
checkout, edición y confirmación de pagos.

La consulta corregida convierte únicamente el resultado a texto. Conserva el
bloqueo transaccional de toda la propiedad y la protección Casa completa vs
apartamentos. Se verificó su ejecución en PostgreSQL sin escribir filas. La
creación y edición completas se probaron aparte en PostgreSQL temporal con datos
ficticios; no en producción.

## Correcciones adicionales

| Área | Corrección |
| --- | --- |
| Concurrencia | Hasta tres intentos de la transacción completa exclusivamente ante conflictos de serialización. La disponibilidad se vuelve a comprobar. |
| Fechas | Calendarios envían fechas de calendario, sin depender del huso horario del dispositivo. Comparación de hoy en Chacala (`America/Mazatlan`). Validación de fechas inválidas, salida anterior o igual a llegada y datos administrativos. |
| Renderizado | Calendarios reciben la misma fecha inicial del servidor; se eliminaron divergencias de hidratación entre UTC y visitantes en Auckland. Las etiquetas de fechas y números son deterministas. |
| Prisma/React | Resultados enviados al navegador se copian como objetos simples, sin símbolos internos, conservando los tipos Date. Normalización de fechas de base idempotente. |
| Reservas pendientes | La disponibilidad coincide con el constraint SQL: una reserva pendiente sigue reteniendo las fechas hasta reconciliar Stripe. Un error al cancelar el PaymentIntent conserva la retención. Una tarjeta rechazada puede reintentarse sin liberar fechas prematuramente. |
| Correos | La reserva manual comprueba el resultado del envío de invoice y conserva el registro ante un fallo. El cron no envía automáticamente los invoices manuales omitidos. |
| Administración | Comprobación de errores HTTP al eliminar reservas/bloqueos y al sincronizar. Se corrigen estados de carga en errores de conexión y un spinner de navegación que podía quedar abierto. |
| Precios | Las tarifas especiales se filtran por unidad. Fechas y cantidades validadas; ya no se truncan silenciosamente decimales al introducir precios enteros. Anticipos configurados distintos de 0/50/100 aparecen en los formularios. |
| Móviles | Calendario dimensionado por su contenedor, formularios apilados en pantallas pequeñas, altura dinámica y desplazamiento de modales. Cierre con Escape, foco dentro del diálogo y retorno de foco al cerrar. |
| Animaciones | Componentes de departamentos definidos fuera del render para evitar remontajes. Se conserva el funcionamiento de botones con movimiento reducido. |
| Recorridos | Un timeout ya no cuenta dos veces el mismo fotograma; limpieza de imágenes/timers y menor concurrencia en dispositivos táctiles. Ante fallo de la primera imagen se muestra una fotografía y un aviso, evitando un lienzo negro. |
| Recursos públicos | El proxy de idiomas ya no redirige archivos estáticos, robots o sitemap. En producción se observaron robots.txt, sitemap.xml e icon.svg redirigidos a /es/ y respondiendo 404 antes de esta corrección. |
| iCal | Importación bajo el mismo bloqueo transaccional. Exportación sin motivos privados de bloqueos. Se mantienen rutas y formatos existentes. |
| Limpieza | Retirados componentes sin referencias, plantilla de correo obsoleta, acción duplicada, imports/estados sin uso, script iCal reemplazado por pruebas y SQL antiguo con semántica de solapamiento incompatible. Helpers locales de parche movidos fuera del proyecto. |

## Prevención y verificaciones

- `npm run verify`: lint sin advertencias, TypeScript, 20 pruebas y validación de Prisma.
- `npm run test:db`: prueba explícita del bloqueo real, sin escrituras. Requiere acceso al PostgreSQL configurado. CI lo ejecuta contra su propio servicio PostgreSQL 16 aislado.
- Compilación final de producción con Next.js y webpack: correcta, 19 páginas generadas. Inicio mediante `next start` contra la base aislada: /es, /en, robots, sitemap, icono, disponibilidad e iCal responden 200; administración sin sesión redirige al login (307).
- Workflow de GitHub añadido para verificar y compilar cada PR/push a main, recrear el esquema con las migraciones y probar el bloqueo contra PostgreSQL 16 aislado. Su ejecución remota ocurrirá al subir estos cambios.
- Vercel ejecuta `npm run verify` antes del build. No se cambiaron los horarios cron.
- Prisma CLI usa `DIRECT_URL` para operaciones administrativas cuando está presente.

Las pruebas de navegador se ejecutaron en una base PostgreSQL temporal recreada
con las migraciones del proyecto, usuario ficticio y servicios reales de cobro y
correo deshabilitados. Se comprobó creación manual, conservación de fechas desde
Auckland, edición, HTML de invoice y visualización de errores de correo.

Se verificaron además bloqueo de un solo día, rechazo de cero noches, interacción táctil, respuesta de fotografía alternativa al fallar el recorrido y recursos /icon.svg, /robots.txt y /sitemap.xml sin redirecciones.

Chrome/Chromium: calendario y formulario público/administrativo en 320×740,
390×844, 768×1024, 1024×768 y 1440×900. Páginas de Tierra, Agua y Aire, ruta `/en`,
disponibilidad y feed iCal. En `next start`, precios especiales diferentes para
Agua/Aire se mostraron únicamente en su unidad, sin errores de hidratación desde
Auckland. Las capturas se inspeccionaron visualmente.

No equivale a una certificación sobre todos los dispositivos físicos. WebKit no
pudo instalarse porque Playwright no soporta el macOS 12 del entorno. Safari/iOS
real requiere una verificación posterior.

`npm audit --omit=dev`: cero avisos altos/críticos; cuatro avisos bajos de la cadena
`@react-email/components` → `@react-email/render` → `html-to-text` → `deepmerge`,
sin corrección disponible en el registro consultado. No se aplicaron actualizaciones
forzadas ni cambios de versión mayores.

## Despliegue y límites

La CLI de Vercel respondió `Not authorized` al consultar el acceso existente. Los
cambios no están activos en casaamapa.com. Este informe no presenta como resuelto
el incidente de producción hasta publicar y comprobar el deployment.

No se necesitan migraciones nuevas para estas correcciones. Para publicar,
verificar y compilar el mismo estado del código, revisar Preview y desplegarlo
con acceso al proyecto Vercel. Después comprobar el formulario administrativo,
los recursos públicos, disponibilidad y los feeds.

Una prueba real de pago/webhook/correo requiere Stripe Test y Resend configurados
en un Preview aislado según README. No se hicieron cobros ni envíos reales. La
sincronización con OTAs sigue dependiendo de la frecuencia de lectura iCal de cada
plataforma; el cron diario de Vercel Hobby puede mantener una retención abandonada
hasta su siguiente reconciliación. No se liberan fechas sin verificar Stripe.
